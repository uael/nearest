# nearest — design

This file is the specification. Code, tests and documentation follow it.

## The idea

A `Region<T>` keeps a `T` and everything it points to in one buffer. A pointer is a `Near<T>`:
4 bytes holding the distance from its own address to its target. So:

- copying the buffer copies the whole value: `Clone` is a `memcpy`;
- reading is plain `&T`, with `Near` dereferencing like `Box`;
- the bytes mean the same at any address, so a region can be written out and read back.

Stable Rust, `#![no_std]` + `alloc`, no dependencies besides the macro. One opt-in feature,
`nightly`, for nightly compilers only.

## Example

```rust
use nearest::{Edit, Near, Region, flat};

#[flat]
struct Block { id: u32, insts: Near<[Inst]>, next: Option<Near<Block>> }
#[flat]
struct Inst { op: u8, args: Near<[u32]> }

// Build. Constructors take anything that can be written as the field's type.
let mut r = Region::new(Block::new(0, (Inst::new(1, [10, 20, 30]), Inst::new(2, ())), None));

// Read. It is `&Block`.
assert_eq!(r.insts[0].args[1], 20);

// Edit. `r.edit()` is `&mut Edit<Block>`; every field has a method of the same name.
let b = r.edit();
*b.id() = 7;
b.insts().push(Inst::new(9, [1, 2])).args().push(3);   // `push` returns the new element
b.insts().at(0).args()[1] = 21;                         // plain data is a real slice
b.insts().retain(|inst| inst.op != 2);

// Move. A value that leaves its place can be written anywhere else in the region, in O(1).
let inst = b.insts().remove(0);                                 // like `Vec::remove`
b.next().insert(Block::new(1, (), None)).insts().push(inst);    // the instruction changes block
let tail = b.next().take();                                     // like `Option::take`
drop(tail);

// Compact. A copy into a new region keeps only what is reachable.
r = Region::new(&*r);

// Save and load. Loading checks the bytes.
let bytes = r.to_bytes();
let copy = Region::<Block>::from_bytes(&bytes)?;
// A memory-mapped file, or any 8-aligned slice, is read in place.
let block: &Block = Region::view(map)?;
```

```rust
#[flat]
enum Expr { Lit(i64), Neg(Near<Expr>), Add(Near<Expr>, Near<Expr>) }

/// `--x` becomes `x`, bottom up.
fn simplify(e: &mut Edit<Expr>) {
  match e.as_mut() {
    ExprMut::Lit(_) => {}
    ExprMut::Neg(x) => simplify(x),
    ExprMut::Add(args) => { simplify(args._0()); simplify(args._1()); }
  }
  if let ExprMut::Neg(x) = e.as_mut() && let ExprMut::Neg(y) = x.as_mut() {
    let inner = y.replace(Expr::Lit(0));     // like `mem::replace`: the old value comes back
    e.set(inner);                            // and moves up, O(1)
  }
}

let mut r = Region::new(Expr::add(Expr::Lit(1), Expr::neg(Expr::Lit(2))));
let e = r.edit();
simplify(e);
let old = e.replace(Expr::Lit(0));
e.set(Expr::neg(old));                       // wrap: the old value moves, O(1)
if let ExprMut::Neg(x) = e.as_mut() && let ExprMut::Add(args) = x.as_mut() {
  let a = args._0().replace(Expr::Lit(0));   // swap two children: three moves
  let b = args._1().replace(a);
  args._0().set(b);
}
```

## Public surface

| Item | Members |
|---|---|
| `#[flat]` | attribute for structs and enums |
| `trait Flat` | `type Edit<'e>: ?Sized`; the rest is hidden |
| `trait Emit<T>` | all hidden; "can be written as a `T`" |
| `type Edit<'e, T>` | `<T as Flat>::Edit<'e>`, the handle type of a place holding a `T` |
| `Near<T>` | `new`, `from_iter` (builders); `as_pin_mut`, `iter_pin_mut` (pinned view) |
| `Region<T>` | `new`, `edit`, `to_bytes`, `from_bytes`, `view`, `byte_len`, and the `unsafe` `from_bytes_unchecked`, `view_unchecked` |
| `ListEdit<'e, T>` | `push`, `insert`, `remove`, `swap`, `truncate`, `retain`, `at`, `try_at`, `set`, `replace`, `update`, `iter_pin_mut` |
| `OptionEdit<'e, T>` | `as_mut`, `insert`, `take`, `set`, `update` |
| `StrEdit<'e>` | `set`, `replace`, `update` |
| `Old<'e, T>` | none: a value that left its place; it can only be written somewhere |
| `Invalid` | none: the error of `from_bytes` and `view` |

Generated by `#[flat]`, for a type `X`:

- struct: `X::new(fields..)`; a handle with `set`, `replace`, `update`, `pin` and one method per
  field;
- enum: one constructor per non-unit variant, in snake case; a handle with `set`, `replace`,
  `update`, `pin` and `as_mut`; and the enum `XMut<'a, 'e>` that `as_mut` returns;
- both: `X::project`, and the type `XPin<'a>` it returns (see "The pinned view").

Trait impls: `Region`: `Deref`, `Clone`, `Debug`, `PartialEq`, `Eq`. `Near`: `Deref`, `Debug`,
`PartialEq`, `Eq`, `PartialOrd`, `Ord`, `Hash`, and `IntoIterator` for `&Near<[T]>`. Handles:
`Deref`, and `DerefMut` for plain data. `Invalid`: `Debug`, `Display`, `Error`, `Clone`,
`PartialEq`, `Eq`. Hidden plumbing for the macro lives in
`nearest::__private`. Nothing else is public.

The cargo feature `nightly` (forwarded to `nearest-derive`) makes `#[flat]` mark every type
`#[pin_v2]`, so that patterns on a pinned value bind its fields pinned (see "The pinned view").
It adds no public item. It needs a nightly compiler for the whole build, and uses
`specialization` (in `nearest`) and `allow_internal_unstable` (in `nearest-derive`) inside the
two crates; crates that use `#[flat]` need no `#![feature]` for it. Without the feature,
nothing changes.

## Stored types

`Flat` is implemented for:

| Type | `Edit` | Notes |
|---|---|---|
| `u8`..`u64`, `i8`..`i64`, `f32`, `f64`, `bool`, `char`, `NonZero<_>` of those integers | itself | |
| `[T; N]`, `T: Flat + Copy`, `N > 0` | itself | |
| `Near<T>`, `T: Flat` | `Edit<'e, T>` | the handle is the target's handle |
| `Near<[T]>`, `T: Flat` | `ListEdit<'e, T>` | |
| `Near<str>` | `StrEdit<'e>` | |
| `Option<Near<T>>`, `T: Flat` | `OptionEdit<'e, T>` | 4 bytes, `None` is 0 |
| `#[flat]` types | generated | |

`Flat` requires `'static`: a stored type has no lifetime. Every stored type has alignment at
most 8, non-zero size and no drop glue. These are checked at
compile time (in a `const` block that every use instantiates: building, editing and checking
bytes).

Plain data means `T: Copy`. A `Copy` type cannot contain a `Near`, so it is safe to hand out as
`&mut T`.

## Layout

- The root is at position 0. The buffer is 8-aligned and grows by doubling.
- `Near<T>`: `NonZero<i32>`, target address minus own address.
- `Near<str>` points at a `u32` length; the bytes follow.
- `Near<[T]>` points at a `u32` length; the elements follow at `+4`, and a `u32` capacity sits
  at `-4`. A list block is `[cap][len][elements]`, aligned to `max(4, align_of::<T>())`; for
  8-aligned elements the block starts at a multiple of 8, so the elements do too.
- `#[flat]` adds `#[repr(C)]` to structs (unless they are already `C` or `transparent`) and
  `#[repr(u8)]` to enums, so the layout does not depend on the compiler's field ordering. Variant
  field offsets come from hidden `#[repr(C)]` mirror structs `(u8, fields..)`.
- A region holds at most `i32::MAX & !7` bytes, so that every distance fits the offset.

## Runtime checks

Aliasing, lifetimes, moves and the tree shape are enforced by types; nothing about them is
checked while a program runs. What is checked at run time is what cannot be known before:

- **Size.** Growing a region past 2 GiB panics, before anything changes. It is the capacity
  overflow of `Vec`, at the size a 4-byte offset can span, and it is only looked at when the
  buffer reallocates.
- **Indices.** `at`, `insert`, `remove` and `swap` panic out of bounds, like slice indexing;
  `try_at` is `at` without the panic.
- **Loaded bytes.** `from_bytes` and `view` check bytes that come from outside and return a
  `Result`; see Bytes. A region built or edited in the program is never checked, and the
  `unsafe` unchecked forms skip the check for bytes the caller trusts.

## Invariants

- **I1 — only in a region.** A `Near` has no constructor and is not `Clone`/`Copy`, so one only
  exists inside a region, and a `&Near` always has its target at the stored offset.
- **I2 — never `&mut` to a pointer.** No safe API yields `&mut T` for a `T` that contains a
  `Near`. Such places are reached through handles, which are unsized, so they cannot be
  swapped, moved out of or assigned through.
- **I3 — one handle chain.** A handle borrows its parent handle mutably, and the root handle
  borrows the region mutably. So at most one handle is usable at a time, no `&T` into the buffer
  is live while a handle can allocate, and a `&mut` to plain data obtained from a handle is
  unique. This is what makes growing the buffer during an edit sound.
- **I4 — a tree.** Every target has exactly one owning pointer. Builders make fresh targets,
  `&T` copies deeply, and the only moves are `Old` (affine, one use) and list operations.
- **I5 — append only.** Data in the buffer is never freed, and bytes that are no longer
  reachable from the root are never written again. Positions stay valid when the buffer grows.
  So a value that left its place (`Old`) stays intact, with everything it points to, for as
  long as the edit lasts.
- **I6 — copies come from elsewhere, moves do not allocate.** A deep copy (`store` with
  `shift == None`) never reads from the buffer it writes to: a `&T` into a region cannot
  coexist with a handle of that region, and an `Old` of the same region is moved, not copied.
  A move (`shift == Some(d)`) only writes the destination.
- **I7 — panics leave a valid value.** A place is either unchanged or holds the complete new
  value. List lengths are written after the element.
- **I8 — one provenance per edit.** `Region::edit` stores the address of the region's `Buf` in
  the `Buf` itself (`me`). A handle only ever reads `me` through its own reference; every other
  access of the edit, by any handle or `Old`, goes through the pointer read from `me`. So no
  access of an edit can invalidate a pointer kept by another part of it (Tree Borrows).
- **I9 — an edit stays on one thread.** Handles and `Old` are neither `Send` nor `Sync`. An
  `Old` reads its region without borrowing a handle (when it is copied into another region),
  so a handle on another thread could grow the buffer under it. Real references obtained from
  a handle (`&T`, `&mut` to plain data) and the `Region` itself are `Send`/`Sync` as usual.

## Handles

A handle is a `&mut` to an unsized type whose only field is `[()]`. The reference is fat: its
address is the region's `Buf` object, which cannot move while the region is borrowed, and its
slice length is the position of the place. A handle therefore never holds an address inside the
buffer and stays valid across reallocation; real references into the buffer (`&T` from `Deref`,
`&mut` to plain data) borrow the handle and so cannot outlive the next allocation (I3).

```rust
#[repr(transparent)]
pub struct Raw<'e, T>(PhantomData<(&'e mut (), T)>, [()]);     // nearest::__private
// &'a mut Raw<'e, T> == (*mut Buf, position)
```

A handle has two lifetimes: `&'a mut Edit<'e, T>`. `'e` is the edit, that is the borrow of the
region taken by `Region::edit(&'e mut self) -> &'e mut Edit<'e, T>`; it is the same for every
handle of the edit. `'a` is the borrow of the parent handle. Both can be left out in the usual
case, `fn pass(e: &mut Edit<Expr>)`; a function that returns a handle or an `Old` names them:

```rust
fn first<'a, 'e>(e: &'a mut Edit<'e, Block>) -> &'a mut Edit<'e, Inst> { e.insts().at(0) }
fn pop<'e>(list: &mut Edit<'e, Near<[Inst]>>) -> Old<'e, Inst> { list.remove(0) }
```

`ListEdit<T>`, `OptionEdit<T>`, `StrEdit` and every generated handle are `#[repr(transparent)]`
wrappers of `Raw<_>`. `Flat::edit(buf, at)` (hidden) builds the handle of a place; for `Near<T>`
it reads the offset and returns the target's handle.

Access discipline (Tree Borrows): a method reads `me` from the handle once (I8) and does
everything through that pointer, each access a reborrow that ends with the statement. `Sink`
and `Old` hold the same raw pointer, never a `&mut Buf`.

What handles offer:

| Place | Handle | Operations |
|---|---|---|
| plain `T` | `&mut T` | ordinary Rust |
| `#[flat]` struct | generated | `field()` for every field, `set`, `replace`, `update`; `Deref<Target = T>`; `DerefMut` if `T: Copy` |
| `#[flat]` enum | generated | `as_mut()`, `set`, `replace`, `update`; `Deref`; `DerefMut` if `T: Copy` |
| `Near<[T]>` | `ListEdit<'e, T>` | list operations, `set`, `replace`, `update`; `Deref<Target = [T]>`; `DerefMut` if `T: Copy` |
| `Option<Near<T>>` | `OptionEdit<'e, T>` | `as_mut() -> Option<&mut Edit<'e, T>>`, `insert(value) -> &mut Edit<'e, T>`, `take() -> Option<Old<'e, T>>`, `set`, `update`; `Deref<Target = Option<Near<T>>>` |
| `Near<str>` | `StrEdit<'e>` | `set`, `replace`, `update`; `Deref<Target = str>` |

Field methods are named after the field (`_0`, `_1`, .. for tuple fields), have the field's
visibility and return `&mut Edit<'e, FieldType>`. Names the generated code uses itself get a
trailing underscore: a field called `set`, `replace`, `pin` or `update`, and the constructor
of a variant called `Project`. Next to a type `X`, `#[flat]` defines `XPin` and, for an enum
with fields, `XMut`; an item of your own with one of those names is a duplicate definition.

`XMut<'a, 'e>` has the variants of `X`, all tuple-like. A unit variant stays a unit; a variant
with one field holds `&'a mut Edit<'e, Field>`; a variant with several fields holds one
`&'a mut` handle with a method per field, because two handles cannot be live at once (I3).
That payload handle has no `set` or `replace`, so the variant cannot change under it. Enums
with only unit variants get no `as_mut`. Generated handle types have the visibility of `X`.

## The pinned view

One handle is usable at a time (I3). Where an edit only reads, writes plain data or assigns
values without pointers, several places can be borrowed together through `Pin`:

```rust
let block: Pin<&mut Block> = b.pin();            // on the handle of every `#[flat]` type
let BlockPin { mut id, insts, next } = block.project();   // every field, pinned, at once
for inst in insts.iter_pin_mut() {               // every element at once
  *inst.project().op += 1;
  *id += 1;
}
if let Some(next) = next.as_pin_mut() {          // `Option::as_pin_mut`, from `core`
  bump(next.as_pin_mut());                       // `Near::as_pin_mut`: the target
}
```

- `pin(&mut self) -> Pin<&mut X>` borrows the handle, so nothing can grow the buffer while a
  pin lives: a pin holds an address, which is exactly what growing would invalidate. Nothing is
  pushed, built or moved through a pin; that is what handles are for.
- `X::project(self: Pin<&mut X>) -> XPin<'_>` is generated: `XPin` has the fields of a struct,
  or the variants of an enum with their fields, each as `Pin<&mut Field>`. On nightly Rust a
  type that is also marked `#[pin_v2]` is projected by patterns, in a crate that enables
  `pin_ergonomics`: `match e.pin() { Expr::Add(a, b) => .. }`. Mark it by hand, or enable the
  `nightly` feature, under which `#[flat]` marks every type.
- `Near::as_pin_mut` pins the target of a pointer, `Near::<[T]>::iter_pin_mut` the elements of
  a list (also on `ListEdit`), and `core` provides `Option::as_pin_mut`.
- A `Near` is `!Unpin`, and a stored type is `Unpin` exactly when its fields are: the macro
  implements `Unpin` under a bound on all the fields, which makes an impl written by hand a
  conflict. So a `Pin<&mut T>` gives a `&mut T` only for data without pointers (I2), where it
  is harmless. A `Region` is always `Unpin`: it owns its buffer.
- A type marked `#[pin_v2]` cannot have that impl: in a crate that enables `pin_ergonomics`,
  the compiler forbids every `Unpin` impl of such a type, the macro's and a hand-written one
  alike. So the macro writes none, and in that crate the compiler keeps the rule. Under the
  `nightly` feature every type is `#[pin_v2]`, also in crates without `pin_ergonomics`, where
  the compiler accepts a hand-written `Unpin` impl. There the check is the library's: every
  place that hands out a `Pin<&mut T>` (`pin`, `Near::as_pin_mut`, `iter_pin_mut`) evaluates,
  at compile time, a hidden constant of `T` that asks, through `specialization`, whether `T`
  and each type it holds by value is `Unpin`, and fails the build if one is while one of its
  fields is not. A hand-written impl on a type holding a `Near` is thus rejected when the type,
  or a type holding it by value, is first pinned; an impl on data without pointers is accepted,
  and harmless.
- `Pin::set` assigns a value held by value, which cannot contain a pointer (I1): the place then
  holds a complete value, and what it pointed to is garbage, as after `set` on a handle.

## Moving values

A handle of a place holding a `T` has three forms of assignment: the two that Rust has, and
one that builds the new value from the old one (an optional pointer has `take` in place of
`replace`):

```rust
pub fn set(&mut self, value: impl Emit<T>)                    // `*place = value`
pub fn replace(&mut self, value: impl Emit<T>) -> Old<'e, T>  // `mem::replace(place, value)`
pub fn update<'a, E: Emit<T>>(&'a mut self, f: impl FnOnce(Old<'a, T>) -> E)
```

`set` keeps the old bytes of the place on the stack while the new value is written, and puts
them back if that unwinds (I7). It allocates nothing for the old value.

`replace` first moves the old value to `size_of::<T>()` fresh bytes (a move re-aims its
pointers; its targets stay where they are), then writes the new value. If that unwinds, a guard
moves the old value back. It returns an `Old` that designates the moved value.

`Old<'e, T>` is a value that left its place and still lives in the buffer of its region, where
nothing reaches it any more (I5). It comes from `replace`, `update`, `ListEdit::remove` and
`OptionEdit::take`, and it implements `Emit<T>`:

- written into a place of its own region, it moves there: `size_of::<T>()` bytes are written
  and its pointers re-aimed, whatever the size of what it points to;
- written into another region, or given to `Region::new`, it is copied from its own region;
- dropped, it is garbage until the region is compacted.

It is neither `Copy` nor `Clone`, so it is used at most once (I4). It holds `(me, position)`,
no address into the buffer, so it stays valid while the buffer grows. Its lifetime is the edit,
`'e`: the region stays mutably borrowed while an `Old` is alive, so the region cannot be read,
replaced, dropped or edited through a second `Region::edit` in the meantime, and an `Old`
never reaches a later edit. It cannot be read: a reference into the buffer would not survive
the next allocation, and nothing ties an `Old` to the handle that allocates. Read a value
through its handle before moving it.

`update` needs no placeholder to build the new value around the old one:
`e.update(|old| Expr::add(old, Expr::Lit(1)))`, or just `e.update(Expr::neg)`, moves the old
value aside, calls `f` and writes its result; if `f` or the writing unwinds, the old value moves
back. Here the `Old` lives as long as the borrow of the handle, `'a`, not as long as the edit.
That is what makes the closure form sound: an `Old` that leaves the closure keeps the handle,
and with it every handle of the region, borrowed for as long as it lives. So it can never be
written into its own region after the old value has moved back; in another region it is a
copy, as always.

With these, every rearrangement is a sequence of ordinary statements: wrap (`update`, or
`replace` the value with a placeholder and `set` the wrapper built around the old value), hoist
(`replace` the child, `set` the parent), swap, rotate, and moving list elements or whole lists
between distant places.

## Lists

`push` and `insert` return the handle of the new element. `push` writes into spare capacity
and then bumps the length; a full list moves to a new block
of twice the capacity (at least 4) and its pointer is re-aimed. `insert`, `remove`, `swap` and
`retain` move elements inside the block; each move re-aims the element's pointers, and plain
elements are moved with `memmove`. `remove` first moves the element out to fresh bytes and
returns it as an `Old`. `truncate` only writes the length. `at(i)` is the handle of
element `i` and panics out of bounds, like indexing; `try_at(i)` returns `None` instead. `retain` keeps the unvisited elements if
its closure panics.

## Building

`Emit<T>` is implemented for:

| Target | Builders |
|---|---|
| any `T` | `T` by value, `&T` (deep copy), `Old<'_, T>` (move; for a list or string place, `T` is `Near<[U]>` or `Near<str>`) |
| `Near<T>`, `Option<Near<T>>` | `Near::new(e)` |
| `Near<[T]>` | `[E; N]`, tuples up to 12 and `()`, `&[T]`, `Near::from_iter(iter)` |
| `Near<str>` | `&str` |
| `#[flat]` types | the generated constructors |

Constructors return `impl Emit<Self>` and are lazy: nothing is written until the builder
reaches a region. Types without pointers can also be built with a plain literal.

Pointers are transparent where that is unambiguous. A constructor parameter for a field
written `Near<X>` takes a builder of `X` and allocates the target, so trees read as
`Expr::add(Expr::Lit(1), Expr::neg(Expr::Lit(2)))`; if `X` is a slice or `str` it takes a list
or string builder. The macro recognizes the field by the name `Near`, and a hidden trait
(`Pointer`) then decides from the type, so `X` may be an alias; a type parameter as `X` is
used as written, so that the argument infers it. A field whose whole type is an alias of a
pointer takes a builder of the pointer, `Near::new(x)`. In the same way the handle of a `Near<X>` place is the
handle of the `X`, so `set` on it takes a builder of `X`, and `OptionEdit::insert` takes a
builder of `X`. An `Option<Near<X>>` parameter takes `None` or `Near::new(x)`.

## Bytes

A region has one compact image: the bytes a deep copy writes. The root is at 0; every target
follows in the order the copy reaches it (depth first, fields in declaration order, list
elements in order), each at the next position aligned for it; lists have `cap == len`; nothing
follows the last target. Builders write the same image.

```rust
pub fn to_bytes(&self) -> Cow<'_, [u8]>
pub fn from_bytes(bytes: &[u8]) -> Result<Region<T>, Invalid>
pub fn view(bytes: &[u8]) -> Result<&T, Invalid>
```

- `to_bytes` borrows the buffer if the region is compact and otherwise returns a compact copy.
  A region is compact when it comes from `Region::new` or `from_bytes`; `edit` clears the mark,
  and so does a list built from an iterator that turned out longer or shorter than its size
  hint said.
- `from_bytes` checks the bytes, at any alignment of the input, and copies them into a new
  region.
- `view` checks the bytes and reads them in place, for example a memory-mapped file. The slice
  must be 8-aligned. A `&T` needs nothing else: `Near` resolves relative to itself.
- `from_bytes_unchecked` and `view_unchecked` are the same without the check, and `unsafe`:
  the caller vouches that the bytes are what `to_bytes` returned for the same type, in a build
  with the same layout. Then loading is one `memcpy`, and viewing reads nothing at all.

Checking accepts exactly the compact images of valid values. It walks the image once, in the
order the copy wrote it, and requires every pointer to aim at the very position where the copy
would have put its target. That one rule gives bounds, alignment, no sharing, no cycles and no
gaps; values are checked on the way: `bool`, `char`, `NonZero`, enum tags, UTF-8, `cap == len`.
Padding is not looked at.

- The checker is safe code: `Flat::check(&mut Check, at) -> Result<(), Invalid>` (hidden,
  generated by `#[flat]`) reads through bounds-checked slices. The only unsafe step is the
  cast of the checked bytes to `&T`.
- It does not recurse. Pointers wait on a stack and the pointers of a list element come before
  the remaining elements, so memory is bounded by nesting depth times fields, time by the
  length of the bytes, and it never panics.
- Lists and arrays of numbers are not walked (`Flat::ANY`: no pointers, and every bit pattern
  is a value). Checking costs time for pointers, text and values that can be invalid, not for
  bulk numbers, so a large memory-mapped table is ready at once.
- The bytes hold native-endian integers and the layout of the target; there is no header or
  version. What `to_bytes` wrote, a build with the same layout reads back.

## Internals

- `Buf`: `Vec<MaybeUninit<u64>>` plus a length in bytes, `me` (I8) and the compact mark;
  zero-filled growth; `len <= capacity` and `capacity <= MAX` hold also while unwinding.
  `Buf` is `Send` and `Sync` by an explicit impl, because of `me`.
- `Sink`: a `*mut Buf`; `alloc`, `write`.
- `Flat::store(&self, sink, at, shift)`: `None` deep-copies targets; `Some(d)` keeps targets and
  re-aims offsets for a move by `d` bytes and never dereferences a `Near`. `Flat::PLAIN` types
  are copied as bytes.
- Self-relative pointers are resolved from `&self`. This is valid under Tree Borrows and not
  under Stacked Borrows. No pointer is made from an integer. Miri runs with
  `-Zmiri-tree-borrows -Zmiri-strict-provenance`.

## Toolchain

The crates build on stable Rust (pinned in `rust-toolchain`). A pinned nightly is used by
`cargo xtask fmt` (unstable rustfmt options), by Miri, and by the `nightly` feature, which is
tested on it, under Miri too.

## What is not here, and why

- No sibling handles that can grow the buffer. Three things cannot hold together: several
  live handles, real references into the buffer, and a buffer that grows in place. Growing may
  move the buffer, so a reference obtained through one handle would dangle when another handle
  grows it. No language feature changes that; only a buffer that never moves would, which a
  growable heap allocation is not. So there are two views: handles grow the buffer, one at a
  time, and the pinned view borrows several places at once, without growing. A value moves
  between two places through an `Old`.
- No sibling swap in the pinned view: two pins do not say whether they are in the same region,
  and a pointer cannot be re-aimed across regions.
- A pin cannot be turned back into a handle: it has an address, not a position in a buffer.
- No single-lifetime handles. A moved value must outlive the borrow of the handle it was taken
  through, or it could not be written into another place; that longer borrow is `'e`. Both
  lifetimes are elided wherever a handle is only passed down.
- No reading of an `Old`, and no `Old` kept across two calls of `Region::edit`.
- No handle or `Old` sent to another thread (I9). Send the `&mut Region` and edit there, or
  send the `&mut [T]` of plain data.
- No in-place reuse of freed space: compact with `Region::new(&*region)`.
- Copies recurse once per level of nesting (`Region::new(&*region)`, and so `to_bytes` of an
  edited region), like `Clone` for a `Box`. Checking bytes does not.
